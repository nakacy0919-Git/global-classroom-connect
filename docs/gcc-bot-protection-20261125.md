## Protection
Optional operator-controlled per-event bot policy, default off. For a protected event the client loads an explicit Cloudflare Turnstile widget with action gcc_roster and event UUID as cData. The Edge Function accepts only eventId and provider token, validates the exact allowed origin, hostname, action and event against Siteverify, and rejects errors. No roster/name/email is included in that verification request. The server-only receipt issuer receives only the event ID and challenge digest; it is callable by service_role, not anon/authenticated. A unique digest prevents repeat issuance for a provider token. Receipt is random, event-bound, valid for two minutes and consumed in the same transaction as signup; failed registration rolls back receipt, invitation and other counter changes. The common INSERT trigger covers V6/V8/V165/V237/V239 on protected events. V239 preserves the caller's JWT and V238 teacher verification. No automatic downgrade to open registration.

The frontend loads the third-party widget only for protected events and preserves the entered roster on failed verification. The verifier does not forward the roster, teacher, or email. Review third-party script, provider privacy terms, CSP, cookies and school-device policy before handling actual student data. Turnstile is a bot-risk reduction, not proof of identity or a complete DoS prevention mechanism. CORS is not authentication. Request-level limits at the trusted gateway and monitoring of abuse/availability remain necessary. Provider verification uses the configured server secret, never a browser key. No live credentials or real challenges were generated.
