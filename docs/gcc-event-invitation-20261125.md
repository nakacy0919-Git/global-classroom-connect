## Proposed opt-in policy
Existing open sessions remain open by default. A global GCC Host Admin (existing gcc_v6_require_host authorization, not every approved teacher) can explicitly switch an upcoming published managed session to invitation-only by issuing its first code from the roster management panel. This is a policy choice requiring host confirmation. Issue one code per school privately. Each code is random, event-bound, one-use, and expires at the earlier of seven days or the session start. Only its SHA-256 digest is stored. Issuance returns the secret once; it is not retrievable later. The host may revoke all unused codes, which keeps the event protected. The UI does not allow reverting to open registration. Existing registrations are not modified. No real codes were issued.

New registration RPC atomically redeems a token, uses a private transaction-scoped single-insert permit and delegates to the original V165/V8 validation, capacity and pair handling. The table trigger rejects all new unpermitted inserts for protected events, including old V6/V8/V165 clients. An error rolls back redemption, permit and burst counter together. No fallback from invalid invitation to open registration. Public form uses a masked field rather than a URL; missing/invalid token returns to the entry step while retaining roster values. Host panel clears the displayed code on close. No new student-data storage.

## Scope and remaining risk
A bearer invitation proves possession, NOT the teacher's real identity or school affiliation. Share codes privately. A stolen/forwarded code can be redeemed once by its holder. Need verified teacher/school identity or host-checked invitations and request-level bot controls before general worldwide launch; open-by-default events are not protected by the invitation gate. Legacy capacity checks on open sessions are unchanged. Existing host role is global admin, not event-owner authorization for ordinary teachers. Review eligibility and per-event limits with event owners before opt-in. No raw codes in URLs, analytics, screenshots or logs; confirm actual Supabase/PostgREST logging settings and secret handling in independent test environment. Test concurrent redemption, expiry, cancellation, host admin UX, mobile input and genuine school workflow there.

Do not delete existing registrations or blindly disable admission triggers. No production SQL, mail, deploy, merge or setting change performed. Require actual teacher/mail/device pilot, leaked-password protection decision and remaining security/backup checks in the worldwide launch runbook.
